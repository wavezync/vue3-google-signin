Google [One Tap](https://developers.google.com/identity/gsi/web/guides/display-google-one-tap)
asks users who are signed in to Google whether to continue as that account,
without leaving the page. The browser draws the prompt through its
[FedCM](https://developers.google.com/identity/gsi/web/guides/fedcm-migration)
API, so how it looks depends on the browser. Like the button, it hands you an
ID token: [verify it on your server](/guide/verify-users/) before you trust it.

:::note
In Nuxt, `useOneTap` is auto-imported: leave out the `import` lines.
:::

## Only prompt signed-out visitors

One Tap is meant for visitors who aren't signed in to your app. Put it in a
component and mount that component only while nobody is signed in. Once the
user signs in, the component unmounts and the prompt goes away.

<Tabs syncKey="framework">
  <TabItem label="Vue">

```vue title="App.vue"
<script setup lang="ts">
import GoogleOneTap from "./components/GoogleOneTap.vue";
import { useAuth } from "./auth"; // your auth state

const { user } = useAuth();
</script>

<template>
  <GoogleOneTap v-if="!user" />
  <RouterView />
</template>
```

</TabItem>
  <TabItem label="Nuxt">

```vue title="layouts/default.vue"
<script setup lang="ts">
const { loggedIn } = useUserSession();
</script>

<template>
  <GoogleOneTap v-if="!loggedIn" />
  <slot />
</template>
```

`GoogleOneTap` is a component that calls `useOneTap`.
[Using with Nuxt](/guide/nuxt/#one-tap-on-every-page) has the whole setup with
nuxt-auth-utils.

## Sign returning users in automatically

With `autoSelect: true`, a returning user who has only one Google session that
approved your app is signed in without a tap:

```ts
useOneTap({
  autoSelect: true,
  onSuccess: ({ credential }) => signIn(credential),
});
```

When they sign out, call `window.google?.accounts.id.disableAutoSelect()`, or
One Tap signs them straight back in. See
[Sign users out](/guide/verify-users/#sign-users-out).

## Change the prompt's wording

`context` picks the title Google shows: `"signin"` (the default), `"signup"` or
`"use"`.

```ts
useOneTap({ context: "signup", onSuccess });
```

## Find out why it didn't show

One Tap doesn't always show. `onPromptMomentNotification` reports what
happened:

```ts
useOneTap({
  onSuccess,
  onPromptMomentNotification: (notification) => {
    if (notification.isSkippedMoment()) {
      console.log("skipped:", notification.getSkippedReason());
    }
    if (notification.isDismissedMoment()) {
      console.log("dismissed:", notification.getDismissedReason());
    }
  },
});
```

The usual reasons:

- **Cooldown.** After a user closes the prompt, the browser waits before
  showing it again, longer each time. Google calls this the
  [exponential cooldown](https://developers.google.com/identity/gsi/web/guides/features#exponential_cooldown).
  Clicking a button that calls `login()` doesn't skip it.
- **Origin.** The page's origin, with its port, must be listed under Authorized
  JavaScript origins for your client ID.
- **No Google session.** The user isn't signed in to Google in this browser, or
  has turned off third-party sign-in prompts in the browser's settings.

Because One Tap can always be skipped, keep a
[sign-in button](/guide/google-signin-button/) on your login page too.
