Google's button is drawn in an iframe, so its [props](/guide/google-signin-button/#style-the-button)
are the only way to change it. For a button in your own design, use one of
Google's OAuth2 flows behind your own `<button>`:

- `useTokenClient`, the [token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model):
  Google gives the browser an **access token**.
- `useCodeClient`, the [code model](https://developers.google.com/identity/oauth2/web/guides/use-code-model):
  Google gives the browser a **code**, which your server exchanges for tokens.

Neither gives the browser an ID token, so finding out who signed in takes one
more step on your server, described [below](#find-out-who-signed-in). If all
you need is sign-in, Google's button is less work.

:::note
A custom Google button has to follow Google's
[branding guidelines](https://developers.google.com/identity/branding-guidelines):
the multicolor G logo, Google's colors and wording such as "Sign in with
Google". The demos on this page follow them.
:::

:::tip
In Nuxt, both composables are auto-imported: leave out the `import` lines.
:::

## With `useTokenClient`

Both composables return `isReady` and `login`:

- `isReady` is a ref that turns `true` once Google's script has loaded and the
  client is ready. Disable your button until then.
- `login()` opens Google's popup. Call it from a click, or the browser blocks
  the popup.

The example below also disables the button while the popup is open. If the
user closes the popup, or the browser blocks it, `onNonOAuthError` re-enables
it.

<Code code={tokenClient} lang="vue" />

<div class="demo not-content">

</div>

The access token is ready to call Google APIs from the browser:
[Call Google APIs](/guide/google-apis/#in-the-browser) shows how to ask for
scopes, check what the user granted and handle expiry.

## With `useCodeClient`

Usage is the same. `onSuccess` receives a `code`, which you post to your server
with an `X-Requested-With` header:

Your server exchanges the code for an access token and a refresh token with your
client secret. [Call Google APIs](/guide/google-apis/#on-your-server) has the
server code for Express and for a Nuxt server route.

## Find out who signed in

- **With a code**, the exchange on your server also returns `tokens.id_token`,
  because `openid` is always requested. Check it with `verifyIdToken` as in
  [Verify users on your server](/guide/verify-users/#verify-it-on-the-server).
- **With an access token**, send it to your server, which asks Google about it.
  `getTokenInfo` from google-auth-library returns the user's `sub` and email,
  and `aud`, the client ID the token was issued for. Check that `aud` is your
  client ID, or a token issued to another app would sign someone in:

```ts
import { OAuth2Client } from "google-auth-library";

const google = new OAuth2Client();

const info = await google.getTokenInfo(accessToken);
if (info.aud !== process.env.GOOGLE_CLIENT_ID) throw new Error("Wrong client");
// info.sub is the user's Google account ID, info.email their email address
```

## Pre-select the account

Both composables pass Google's options through:

- `login_hint`: the user's email address or `sub`, to skip the account chooser
  for a user you already know.
- `hd`: limit the chooser to a Google Workspace domain.
- `select_account: true` (code client) or `login({ prompt: "select_account" })`
  (token client): always show the account chooser, for "Use another account".
