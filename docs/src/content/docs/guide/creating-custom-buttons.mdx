Often, you may want a custom designed button for Google Sign-in.
`vue3-google-signin` provides two composables for this:

- `useTokenClient`: [Token Model authentication flow](https://developers.google.com/identity/oauth2/web/guides/use-token-model)
- `useCodeClient`: [Code Model authentication flow](https://developers.google.com/identity/oauth2/web/guides/use-code-model)

Pick the flow that fits your use case.

:::tip
To choose the right authorization model, see Google's [guide](https://developers.google.com/identity/oauth2/web/guides/choose-authorization-model).
:::

## With `useTokenClient`

With the [Token Model auth flow](https://developers.google.com/identity/oauth2/web/guides/use-token-model), Google returns an **Access Token** to the browser,
which can be used directly to call Google APIs.

:::tip
For backend API requests, you can pass this token from the frontend to the backend in a header like `x-google-token`.
:::

Both composables return `isReady` and `login`:

- `isReady` is a _reactive variable_ that tells you whether the Google API has loaded.
  Use it to disable the button until then, or however suits your application.
- `login` is a _method_ that starts the login flow with Google.

The example below disables the button until the API has loaded, then starts the login flow from the button's `@click` event.

## With `useCodeClient`

With the [Code Model auth flow](https://developers.google.com/identity/oauth2/web/guides/use-code-model), you get a `code` from Google.
Your **backend server** verifies it to obtain user information, an Access Token, a Refresh Token, etc.

Usage is similar to the previous section.
The only difference is an _optional_ part that calls a backend API to verify the code, using the body of a **POST** request.

## Verify code on the backend

Once you have a code, the backend must verify it to get the **Access Token** / **Refresh Token**, as described in the [previous section](#with-usecodeclient).

:::note
This depends on your backend programming language.
:::
